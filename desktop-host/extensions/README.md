# Внешние модули (расширения)

Здесь лежат сторонние модули, изначально сделанные для Owlbear Rodeo.
Их **исходники не редактируются** — они хранятся как есть и адаптируются
на уровне хоста VTT.

## Общая схема адаптации

1. `obr-shim.js` — наш файл в каждом модуле (копия одинаковая). Он реализует
   срез `@owlbear-rodeo/sdk`, который используют расширения:
   `isAvailable`, `onReady`, `player.getRole`, `player.onChange`,
   `scene.getMetadata/setMetadata/onMetadataChange`,
   `room.getMetadata/setMetadata/onMetadataChange` (room и scene в VTT — одно
   и то же хранилище сессии; дублирующая запись отсекается).
2. `id` модуля адаптер определяет по пути `/extensions/<id>/obr-shim.js`,
   а ключ метаданных Owlbear (`metaKey`) получает от хоста сообщением
   `config`. Поэтому один и тот же адаптер работает для всех модулей.
3. HTTP-сервер хоста отдаёт `app.js` с заменой **только URL импорта SDK**
   (CDN → `/extensions/<id>/obr-shim.js`). Файл на диске остаётся неизменным.
4. Состояние модуля хранится в сессии VTT (`extensionState[<id>]`) и
   синхронизируется событием `extension:update`. Мастер пишет через IPC;
   модули с `playerWritable: true` принимают записи и от игроков
   (проверка на сервере).
5. `metaKey` и `playerWritable` объявлены в манифесте модуля
   (`shared/plugins/builtins.ts`), а не в исходниках расширения.

## troika-initiative

«Стек инициативы Тройка!» — трекер инициативы по правилам «Тройки!».
Оригинал: отдельный проект `troika-initiative` (Owlbear Rodeo, manifest v1).

- Состояние: `com.troika.initiative/state`.
- Права: пишет только Мастер, игроки смотрят.

## troika-sheet

«Лист персонажа Тройка!» — редактируемый лист персонажа (A4, печать/PDF).
Оригинал: отдельный проект `troika-sheet` (Owlbear Rodeo, manifest v1).

- Состояние: `com.troika.sheet/state`.
- Права: **любой участник** может редактировать листы (`playerWritable`),
  изменения сразу видны всем и сохраняются в JSON сессии.
- Выбор листа — **у каждого пользователя свой**: `currentId` подменяется
  локально в мосте (`withLocalSelection`), поэтому переключение листа одним
  участником не переключает остальных.
- Правки разных листов объединяются по id (`mergeWithBaseline`): если двое
  редактируют разные листы одновременно, изменения не затирают друг друга.
- Интерфейс: при отдаче `index.html` хост добавляет `<style id="vtt-adapter">`
  и скрывает кнопки «Опубликовать в комнату», «Печать / PDF», «Экспорт»,
  «Импорт» и «Ссылка» — в VTT они не нужны (состояние и так общее).
  Исходный файл не меняется.
- iframe открывается с `sandbox="... allow-modals"`, иначе браузер блокирует
  `confirm()` и кнопка «Удалить» молча ничего не делает.

## azag-sheet

«Лист персонажа AZAG» — редактируемый лист для игры AZAG (Dank Dungeons),
сделанный по PDF-бланку `Лист AZAG А4.pdf`.

- Это **наш** модуль, а не сторонний: `index.html`, `styles.css`, `app.js`
  написаны для VTT.
- `sheet.png` — страница PDF, отрисованная в 3× и используемая как фон.
- `fields.generated.js` — 61 поле PDF-формы (координаты, тип, многострочность),
  сгенерировано из PDF; поля ввода прозрачно наложены на бланк.
- Состояние: `com.azag.sheet/state`, формат как у листа «Тройки»
  (`currentId`, `chars`), поэтому работают независимый выбор листа и слияние.
- Права: редактирует любой участник (`playerWritable`), раздел каталога — «AZAG».

## agon-sheet

«Агон — лист героя» — наш модуль по PDF-бланку «Агона» (Студия 101).

- Несколько листов героев (`currentId`, `chars`), создание/удаление, у каждого
  участника свой выбранный лист; правки сливаются по `id`.
- Состояние: `com.agon.sheet/state`; игроки пишут (`playerWritable`).
- Поля: текст, выпадающие кубики `4/6/8/10/12`, чекбоксы Славы/Имени/Пафоса/
  Судьбы/Подвигов/Наград, 24 ромба Милости богов и 2 ромба у способности.
- Портрет: большой круг кликабелен, изображение обрезается по кругу и
  сжимается до 512 px; хранится в общем состоянии.
- `sheet.png` — страница PDF; `fields.js` — координаты полей из PDF-бланка.
- Окно открывается через `CharacterSheetFrame`.

## dice3d

«3D-кубики» — физические d4–d100 на столе (Three.js + Cannon).
Движок [`@3d-dice/dice-box-threejs`](https://github.com/3d-dice/dice-box-threejs)
(MIT) лежит локально: `dice-box-threejs.umd.js` и текстуры в `assets/`.

- Это **наш** модуль: `index.html`, `styles.css`, `app.js`.
- Состояние в сессии не хранится: бросок локальный, а результат уходит
  в общий чат через postMessage (`type: 'chat'`).
- Иконка модуля — в доке справа сверху, раздел каталога «Базовые».

## Обновление модуля

Скопируйте файлы новой версии оригинала заново (кроме `obr-shim.js`),
проверьте, что используемые места SDK не изменились, и при необходимости
добавьте новый `metaKey` в `shared/plugins/builtins.ts`.
