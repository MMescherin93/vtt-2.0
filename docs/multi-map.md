# Несколько карт в сессии — предложение по реализации

Статус: **проектирование**, код не менялся. Нужно согласовать развилки (в конце файла).

## Что хотим

Мастер загружает несколько карт, они лежат «рядом», а переключение между ними —
перетаскиванием карты/камеры, без модальных окон и списков.

## UX-варианты

### Вариант A. Единое полотно карт (рекомендую)

Все карты выкладываются слева направо с зазором (например, 120 px). Мир — одна
система координат: `worldWidth = Σ ширин + зазор × (n−1)`, `worldHeight = max(высот)`.

- Камера просто панорамируется; перетаскивание мышью/пальцем «листает» карты.
- Токены, туман и рисунки живут в координатах мира и могут лежать на любой карте.
- Слева внизу — мини-индикатор карт («полоса»), по клику камера плавно едет к карте.
- Плюсы: минимум изменений, простые правила (один туман, одни рисунки).
- Минусы: туман/рисунки общие; токен можно поставить в зазор между картами
  (лечится «прилипанием» к ближайшей карте).

### Вариант B. Карты как отдельные сцены

У каждой карты свои токены, туман и рисунки (`mapId` у сущностей), переключение —
свайп/драг по «колоде» карт.

- Плюсы: полная изоляция сцен, как в Owlbear Rodeo.
- Минусы: рефакторинг всех сущностей и событий, миграция JSON, больше UI.

## Предлагаемые изменения (вариант A)

1. **Типы.** `Session.maps: MapAsset[]`, где `MapAsset = { id, imageUrl, width, height }`.
   Старое поле `map` остаётся только для чтения при миграции.
2. **Миграция.** `schemaVersion: 2`; `normalizeSession` при отсутствии `maps`
   собирает массив из `map` (если загружена) и вычищает старый путь.
3. **Геометрия.** Утилита `layoutMaps(maps, gap)` → `{ items: [{map, x, y}], world: {width,height} }`;
   вынести в `shared/utils/maps.ts` и покрыть тестом.
4. **Board.** `field` считается по миру; `MapLayer` рисует все карты по смещениям;
   сетка/туман/рисунки — по миру; токены ограничиваются миром.
5. **MapPanel.** Список карт: добавить, удалить, переставить; загрузка добавляет в конец.
6. **Сервер.** Без изменений протокола: `session:update` уже передаёт всё состояние.
7. **Камера.** При старте вписываем весь мир; двойной клик по мини-индикатору — «вписать карту».
8. **Тесты.** Миграция `map → maps`, раскладка мира, clamp токена в мире.

## Оценка

Небольшой-средний рефакторинг: ~6 файлов ядра (`types/session`, `storage`,
`shared/utils/maps`, `Board`, `MapLayer`, `MapPanel`) + правки README/agent.md.
Изменения данных обратимы (старые сессии открываются миграцией).

## Вопросы для согласования

1. **Туман и рисунки**: общие на весь мир (вариант A) или у каждой карты свои (вариант B)?
2. **Переключение**: панорамирование по общему полотну (A) или отдельная «колода»
   с драгом-свайпом между картами (B)?
3. **Зазор между картами**: пустое тёмное поле 120 px или тонкая рамка с подписью карты?
4. **Пределы**: сколько карт максимум (например, 20) и какой максимальный размер
   файла на карту (сейчас 50 МБ)?
5. **Токены между картами**: разрешить перетаскивать с карты на карту (A) или
   запрещать и «прилипать» к ближайшей (B)?
