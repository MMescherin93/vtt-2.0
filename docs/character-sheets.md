# Листы персонажей: обязательное правило

Статус: **обязательно для всех листов персонажей** — текущих и будущих.

## Правило

Любой лист персонажа в VTT открывается через **`CharacterSheetFrame`**
(`shared/ui/CharacterSheetFrame.tsx`), а не через голый `ExtensionFrame`.

`CharacterSheetFrame` всегда включает:

- масштабирование содержимого **50–200%** кнопками `− / % / +`;
- сброс масштаба кликом по проценту;
- изменение размера окна за правый/нижний край и правый нижний угол;
- запоминание масштаба и размера отдельно для каждого клиента и каждого листа;
- заполнение листом доступной области окна;
- прокрутку при увеличении;
- подстройку под вьюпорт игрока: окно листа не шире и не выше рабочей
  области, открывается ниже верхней панели и не накрывает кнопки управления;
- перетаскивание за заголовок, в том числе когда указатель проходит над
  содержимым iframe.

Отключить эти возможности для листа нельзя: компонент не принимает
`zoomable`/`resizable` — они включены внутри.

## Как добавить новый лист

1. Сделать iframe-модуль листа по общей схеме расширений
   (`desktop-host/extensions/<id>/`, `obr-shim.js`, `metaKey`).
2. Для общего состояния использовать `perClientSelection` и
   `mergeListKey="chars"` (у каждого свой выбранный лист, правки сливаются).
3. Для игроков передать `allowPlayerWrite`, если лист редактируется игроками.
4. В `desktop-host/.../BoardView.tsx` и `web-client/.../BoardView.tsx`
   обернуть лист в `CharacterSheetFrame`.
5. Не добавлять `zoomable`/`resizable` вручную и не использовать
   `ExtensionFrame` для листов.
6. Проверить сценарий из чек-листа ниже.

Пример:

```tsx
<CharacterSheetFrame
  title="Лист персонажа «Новая система»"
  src={`${assetsUrl}/extensions/new-sheet/index.html`}
  extensionId="new-sheet"
  role="gm"
  metaKey="com.example.sheet/state"
  perClientSelection
  mergeListKey="chars"
  state={session.extensionState['new-sheet'] ?? null}
  onChange={(next) => setExtensionState('new-sheet', next)}
  onClose={() => toggleModulePanel('new-sheet', false)}
  width={920}
  height={720}
  storageKey="vtt.gm.panel.new-sheet"
  defaultPosition={{ x: 240, y: 40 }}
/>
```

## Требования к самому листу

- Лист должен нормально выглядеть при разной ширине iframe; не фиксировать
  ширину страницы жёстко, если это возможно.
- Основной контент — в прокручиваемой области; шапка листа не должна
  перекрывать форму.
- Не добавлять собственные кнопки масштаба внутри iframe: этим управляет
  `CharacterSheetFrame`.
- Не блокировать `postMessage`/`obr-shim` при изменении размера.

## Чек-лист проверки

- [ ] Кнопки `− / +` меняют масштаб от 50% до 200%.
- [ ] Клик по проценту возвращает 100%.
- [ ] Окно листа тянется за правый край, нижний край и угол.
- [ ] Окно листа перетаскивается за заголовок, в том числе над содержимым.
- [ ] Окно листа не уезжает за край и не накрывает кнопки управления
      (тулбар, док модулей, переключатель карт): они остаются над листом.
- [ ] На узком экране (ноутбук, планшет) окно ужимается по ширине и высоте.
- [ ] При увеличении окна лист занимает новую ширину/высоту.
- [ ] При уменьшении окна появляется прокрутка, ничего не обрезается насмерть.
- [ ] После закрытия и повторного открытия размер и масштаб сохраняются.
- [ ] После перезапуска приложения размер и масштаб сохраняются.
- [ ] У Мастера и игрока настройки независимы.
- [ ] Изменения листа по-прежнему синхронизируются между участниками.
- [ ] `npm run typecheck`, `npm run lint`, `npm run test:server`, сборка — зелёные.
