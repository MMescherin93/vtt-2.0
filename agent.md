# agent.md — правила разработки VTT 2.0

Файл для людей и ИИ-агентов, которые меняют этот репозиторий. Здесь зафиксированы
архитектурный тип, стек, границы ответственности и обязательные проверки.
Если правило противоречит коду — прав код, правило нужно обновить вместе с ним.

---

## 1. Тип архитектуры: Everything is a plugin

Ядро приложения не содержит функций конкретных фич. Любая пользовательская
возможность — **плагин**: отдельный модуль, который регистрируется в реестре слота
и может быть отключён без поломки ядра.

**Плагин** — это самостоятельная единица, которая:

1. имеет `id`, человекочитаемый `title` и слот (`slot`);
2. регистрируется в реестре своего слота (одна строка в точке сборки);
3. получает зависимости только через контракт (`PluginContext`), а не импортом ядра;
4. не импортирует другие плагины напрямую — общение через общий стор и типы;
5. при отключении оставляет ядро работоспособным.

**Ядро** — это инфраструктура: окно Electron, HTTP/Socket.io сервер, хранилище сессий,
маршрутизация событий, канвас-хост, реестры плагинов, общие UI-примитивы. Ядро не знает,
что такое «кубики», «туман» или «чат» — оно знает только слоты.

### Слоты плагинов

| Слот                | Что регистрирует                                                      | Точка сборки                      |
| ------------------- | --------------------------------------------------------------------- | --------------------------------- |
| `tool`              | инструмент тулбара (иконка, курсор, обработка указателя)              | `HostToolbar` / `ClientToolbar`   |
| `panel`             | плавающая панель (чат, кубики, токены, карта, приглашение, участники) | `BoardView` хоста и игрока        |
| `board-layer`       | слой Konva (карта, сетка, токены, туман, рисунки, текст, превью)      | `shared/ui/Board.tsx`             |
| `server-command`    | IPC-команда главного процесса со своей валидацией                     | `desktop-host/src/main/index.ts`  |
| `socket-event`      | обработчик события сокета (валидация + рассылка)                      | `desktop-host/src/main/server.ts` |
| `session-migration` | миграция схемы JSON при загрузке сессии                               | `storage.normalizeSession`        |
| `extension`         | модуль, который пользователь включает в панели «Расширения»           | `shared/plugins/builtins.ts`      |

### Расширения (пользовательские модули)

Манифест: `ExtensionDefinition { id, title, description, scope, defaultEnabled }`
в `shared/plugins/types.ts`, реестр — `shared/plugins/builtins.ts`.
Панель `ExtensionsPanel` показывает модули по роли и хранит включённость в
`localStorage` клиента. Ядро спрашивает `isExtensionEnabled(...)` и не содержит
`if (extension === ...)`.

Модуль с полями `icon` и `panel: true` получает иконку в доке `ModuleDock`
в правом верхнем углу: иконка видна только у включённого модуля, клик
разворачивает и сворачивает панель (`modulePanels` в сторе).

Каталог расширений разбит на разделы (`ExtensionDefinition.category` +
`EXTENSION_CATEGORIES` в `shared/plugins/builtins.ts`): `basic` — инструменты
стола, `troika` — модули системы «Тройка!», `azag` — модули игры AZAG.
Новый раздел добавляется туда же; неизвестная категория автоматически попадает
в «Другие».

Правило: новая пользовательская фича = новый модуль + строка в реестре + проверки
в точках интеграции (тулбар, панель, слой). Выключение расширения не должно
ломать ядро.

### Внешние модули (Owlbear Rodeo)

В `desktop-host/extensions/<id>/` лежат сторонние модули для Owlbear Rodeo.
Их **исходники не редактируются**. Адаптация — только на стороне хоста:

- сервер отдаёт файлы по `/extensions/<id>/...`;
- для несовместимого SDK допускается подмена URL импорта при отдаче
  (файл на диске не меняется) и локальный адаптер вроде `obr-shim.js`;
- состояние модуля живёт в `Session.extensionState[<id>]` и синхронизируется
  событием `extension:update` (Мастер пишет через IPC, игроки только читают,
  кроме модулей с `playerWritable: true` — им разрешено писать через сокет);
- включённость расширений — общая для сессии (`Session.enabledExtensions`),
  меняет только Мастер через IPC; игроки видят тот же набор и могут лишь
  разворачивать/сворачивать панели иконками (`modulePanels` — локально);
- iframe модуля — `shared/ui/ExtensionFrame.tsx` (sandbox, postMessage-мост).

### Контракт плагина (целевой, вынести в `shared/plugins/types.ts` при первом рефакторинге)

```ts
export type PluginSlot =
  | 'tool'
  | 'panel'
  | 'board-layer'
  | 'server-command'
  | 'socket-event'
  | 'session-migration'
  | 'extension'

export interface PluginContext {
  role: 'gm' | 'player'
  session: Session
  userId: string
  logger: (message: string) => void
}

export interface PluginDefinition {
  id: string
  slot: PluginSlot
  title: string
  /** Порядок в слоте: меньше — выше/раньше */
  order?: number
  activate(context: PluginContext): void | (() => void)
}
```

Контракт расширений уже реализован в `shared/plugins/types.ts`
(`ExtensionDefinition`, `ExtensionValues`, `isExtensionEnabled`).

### Встроенные плагины v1.0

- `tool`: выбор, перемещение, рисование, ластик, туман войны (только GM)
- `panel`: чат, кубики, токены, карта и сетка, приглашение, участники,
  HP/AC и состояния, инициатива
- `board-layer`: карта, сетка, токены, статы, туман, рисунки, текст, слой превью
- `server-command`: сессии, ассеты, токены, туман, рисование, текст, чат, кубики, приглашение/туннель
- `extension-frame`: iframe-модуль, обмен состоянием, масштаб содержимого (`zoomable`) и изменяемый размер окна (`resizable`)
- `socket-event`: `client:join`, `session:request`, `token:move`, `token:update`,
  `chat:send`, `dice:roll`, `drawing:add`, `fog:update`
- `session-migration`: нормализация полей сессии и версии схемы
- `extension`: кубики, чат, рисование, туман войны, подписи токенов,
  3D-кубики, HP/AC и состояния, инициатива, PDF-библиотека, заметки,
  лист «Запретные земли», кубы «Запретных земель», «Тройка! Трекер состояний»,
  «Инициатива «Тройка»», листы «Тройки», AZAG и «Агона»
  (см. `shared/plugins/builtins.ts`)

### Как добавить фичу (обязательный порядок)

1. Создать модуль плагина в профильной папке (`components/<Feature>/`, `shared/ui/plugins/`,
   `main/plugins/`) — **новый файл, не правка ядра**.
2. Добавить в `shared/types` нужные типы и событие, если фича сетевая.
3. Зарегистрировать плагин в реестре слота (одна строка).
4. Добавить серверную валидацию, если фича меняет состояние.
5. Написать проверку (интеграционный тест или ручной сценарий в чек-листе).

**Запрещено** добавлять в ядро ветвления вида `if (feature === 'dice')`; расширение
делается через регистрацию, а не через правку общего кода.

### Листы персонажей — обязательное правило

Все листы персонажей (текущие и будущие) открываются только через
**`CharacterSheetFrame`**, а не через `ExtensionFrame` напрямую. Компонент
обязательно даёт:

- масштаб содержимого 50–200% (`− / % / +`, сброс на 100%);
- изменение размера окна за края и правый нижний угол;
- запоминание масштаба и размера отдельно для клиента и листа.

Не добавляйте `zoomable`/`resizable` вручную и не отключайте их. Полный
чек-лист и пример подключения — [docs/character-sheets.md](docs/character-sheets.md).

## 2. Стек (не менять без явного решения)

| Слой            | Технологии                                      | Версии                                            |

| Хранение        | JSON + `node:fs/promises`, без БД               | —                                                 |
| Качество        | ESLint + Prettier + `tsc --noEmit`              | eslint `^10`, prettier `^3`                       |

## 3. Структура

```
desktop-host/       Electron: main (сервер, сессии, хранение, туннель), preload, renderer (UI Мастера)
web-client/         веб-клиент игрока: React + Vite + Konva
shared/types/       Session, Token, Map/Fog/Drawing/Text, PDF, Note, Combat, WebSocket-события
shared/utils/       камера, сетка, кубики, туман, id, цвета, фабрика сессии
shared/ui/          общий Konva-канвас, плавающие панели, чат, кубики, иконки
scripts/            интеграционный тест, лаунчер, ярлыки, иконка
```

Правило: **общий код живёт в `shared`**, дублировать канвас/панели между хостом и
клиентом запрещено.

## 4. Основные правила

### Роли и данные

- GM — только десктопное приложение; веб-клиенты всегда игроки.
- PDF-библиотека: файлы лежат в папке сессии, в JSON только `Session.pdfs` и
  метаданные; раздача — `application/pdf` с Range. Загружает только Мастер.
- Заметки: `Session.notes` содержит общие и GM-заметки; сервер вырезает
  `visibility: 'gm'` для игроков. Личные «Мои» заметки — в `localStorage`
  клиента и на сервер не уходят. Подробности — [docs/library.md](docs/library.md).
- Статы токенов (`Token.stats`) и бой (`Session.combat`) — данные сессии.
  Сервер отдаёт игрокам только разрешённое: цифры HP/AC по режиму
  `full | bar | hidden`, скрытых бойцов и их имена вырезает `playerCombat`.
  Менять статы и бой может только Мастер (IPC), игроки не могут через сокет.
- GM-only проверяется **на сервере** (`socket.data.role`, IPC-команды), не только в UI.
- Сервер — источник истины: он валидирует размеры, права, лимиты и сохраняет состояние.
- Скрытые токены не попадают игрокам ни в `session:update`, ни в `token:add`.

### Состояние и синхронизация

- `SessionManager.update()` — структурные изменения (полная рассылка `session:update`).
- `SessionManager.updateSilent()` — частые изменения (перетаскивание токена, штрих кисти):
  сохранение + точечное событие (`token:update`, `drawing:add`, `fog:update`), без полной рассылки.
- Новые сетевые события добавлять в `shared/types/events.ts` с обеими сторонами типов.
- Каждое событие логировать (`console.log('[server] ...')`), чтобы отладка была возможна.

### Хранение

- Сессия: `<userData>/vtt-data/<id>/session.json` + `assets/` (в JSON — относительные пути).
- Запись только атомарная (`.tmp` + rename), автосохранение с задержкой ~250 мс.
- Изменение схемы JSON → поднять `schemaVersion` и добавить миграцию в
  `storage.normalizeSession`; старые файлы должны открываться.

### UI/UX

- Тёмная тема (`#1a1a1a`), акцент — индиго, панели полупрозрачные (`backdrop-blur`),
  плавающие и перетаскиваемые, карту не перекрывают целиком.
- Стили — Tailwind-классы; переиспользовать `shared/ui` (`FloatingPanel`, `ToolbarButton`,
  `ChatPanel`, `DicePanel`, `Board`).
- Текст интерфейса и комментарии — по-русски; идентификаторы, типы, события — по-английски.

### Безопасность

- Входящие данные валидировать (`sanitizeFog`, лимиты длины/размера, проверка чисел).
- Пути ассетов — только через `resolveAssetPath` (защита от path traversal).
- Renderer без Node: `contextIsolation: true`, `nodeIntegration: false`, доступ только через preload.
- Не коммитить секреты, токены, `.env.local`, данные сессий.

### Производительность

- Каждый слой — отдельный Konva `Layer`; сетка рисуется одним `Shape` с отсечением по viewport.
- Перетаскивание токена — throttle ~70 мс; полная сессия на каждое движение не рассылается.
- Туман и рисунки хранятся как операции/точки, а не как пиксельная маска.

### Запрещено

- править `node_modules`, `out`, `dist` руками;
- использовать `any` без обоснования и глушить ошибки `@ts-ignore`;
- дублировать общий код вместо `shared`;
- ломать обратную совместимость JSON без миграции;
- менять публичные события сокета без обновления типов и README.

## 5. Окружение Windows и запуск

- В PowerShell скрипты выполнения запрещены — использовать `npm.cmd`.
- Перед запуском Electron убирать унаследованные переменные:
  `ELECTRON_RUN_AS_NODE`, `CHROME_CRASHPAD_PIPE_NAME`.
- **Кириллица в пути к `electron.exe` не даёт Chromium стартовать** (код `0x80000003`
  без вывода). Лаунчер копирует Electron в ASCII-путь `%LOCALAPPDATA%\VTT\electron-<версия>`
  и запускает оттуда. Проект при этом может лежать в папке с русским названием.
- Ярлык: `npm run shortcut`; запуск: ярлык «VTT» или `scripts/launch-vtt.ps1`.
- Логи запуска: `desktop-host/out/launcher.log`, `electron.log`, `electron-error.log`.
- Туннель для игроков: `cloudflared` quick tunnel или ручной адрес в панели «Приглашение».
- Данные: `%APPDATA%\desktop-host\vtt-data` (переопределяется `VTT_DATA_DIR`, порт — `VTT_PORT`).

## 6. Команды

```powershell
npm install            # установка (при сбое postinstall: --ignore-scripts + node node_modules/electron/install.js)
npm run dev:host       # Electron-хост в dev-режиме
npm run dev:client     # веб-клиент игрока на :5173
npm run build          # сборка хоста (out/) и клиента (dist/)
npm run start:host     # запуск собранного хоста (нужен ASCII-путь к Electron)
npm run shortcut       # пересоздать ярлык VTT
npm run typecheck      # tsc strict во всех пакетах
npm run lint           # ESLint
npm run format         # Prettier
npm run test:server    # интеграционный тест сервера
```

## 7. Definition of Done

Задача считается выполненной, когда:

- [ ] `npm run typecheck` и `npm run lint` проходят без ошибок;
- [ ] `npm run build` собирает хост и клиент;
- [ ] `npm run test:server` проходит (если менялись сессии/сокеты/хранение);
- [ ] новая фича оформлена как плагин и зарегистрирована, ядро не обросло ветвлениями;
- [ ] серверная валидация и проверка ролей добавлены;
- [ ] типы и события обновлены в `shared`;
- [ ] README/agent.md обновлены, если изменились команды, формат данных или правила;
- [ ] изменения закоммичены (`git add -A && git commit -m "..."`) и запушены.
