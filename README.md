# VTT 2.0 — виртуальный стол для НРИ

Монорепозиторий по ТЗ: десктопное приложение Мастера (Electron) + веб-клиенты игроков
(React + Vite), синхронизация через Socket.io (порт 3001).

- **Мастер** запускает десктопное приложение: оно поднимает WebSocket-сервер, хранит сессии
  локально в JSON и раздаёт веб-клиент игрокам.
- **Игроки** открывают ссылку-приглашение в браузере — установка не нужна.

> Архитектура проекта — **everything is a plugin**. Стек, границы слоёв, правила разработки
> и чек-лист приёмки зафиксированы в [agent.md](agent.md).

## Структура

```
vtt-app/
├── desktop-host/            # Electron-приложение Мастера (хост + WebSocket-сервер + GM UI)
│   └── src/
│       ├── main/            # главный процесс: окно, сервер, сессии, хранение, туннель
│       ├── preload/         # contextBridge-API окна Мастера
│       ├── shared/          # типы IPC между процессами
│       └── renderer/        # React UI Мастера (стор Zustand, панели, тулбар)
├── web-client/              # веб-клиент игроков (React + Vite + Konva)
├── shared/                  # общие типы, утилиты и UI-компоненты канваса/панелей
│   ├── types/               # session, token, map, events
│   ├── utils/               # камера, сетка, карты, кубики, туман, id, цвета
│   └── ui/                  # Konva-канвас, плавающие панели, чат, кубики, иконки
└── scripts/                 # интеграционный тест сервера
```

## Требования

- Node.js >= 20.19 (проверено на v24)
- npm (в PowerShell с запретом скриптов используйте `npm.cmd`)

## Установка и запуск

```powershell
npm install

# терминал 1: хост Мастера (Electron + Socket.io на :3001)
npm run dev:host

# терминал 2: веб-клиент игроков (Vite, http://localhost:5173)
npm run dev:client
```

В окне Мастера: создайте сессию → откройте её → панель «Приглашение» даст ссылку
`http://localhost:5173/?session=<id>` (в dev-режиме) или `http://<LAN-IP>:3001/?session=<id>`
(если собран веб-клиент — см. ниже).

### Сборка и режим «один порт»

```powershell
npm run build      # собирает desktop-host (out/) и web-client (dist/)
npm run dev:host   # хост найдёт web-client/dist и будет раздавать его на :3001
```

После сборки ссылка-приглашение ведёт на тот же порт 3001 — удобно для туннеля
(наружу открывается один порт).

### Ярлык для запуска приложения

```powershell
npm run build      # один раз собрать приложение
npm run shortcut   # создать ярлык «VTT» на рабочем столе и в папке проекта
```

Ярлык запускает **собранное** приложение (без консоли и npm): скрытый PowerShell-скрипт
[launch-vtt.ps1](scripts/launch-vtt.ps1) проверяет наличие сборки (при необходимости собирает её),
убирает унаследованные переменные `ELECTRON_RUN_AS_NODE` / `CHROME_CRASHPAD_PIPE_NAME`
и открывает `desktop-host` в Electron.

> **Кириллица в пути.** Electron не стартует, если в пути к `electron.exe` есть не-ASCII
> символы (у нас это папка «Проект по умолчанию»). Поэтому лаунчер при первом запуске
> копирует Electron в ASCII-путь `%LOCALAPPDATA%\VTT\electron-<версия>` (≈250 МБ, пара секунд)
> и запускает уже оттуда — окно открывается нормально. Проект при этом может оставаться
> в папке с русским названием.

Если папка проекта переехала, ярлык нужно пересоздать: `npm run shortcut`.

- Лог запуска: `desktop-host\out\launcher.log`, вывод Electron — `desktop-host\out\electron.log`
  и `electron-error.log`.
- Повторный запуск ярлыка при уже открытом VTT просто фокусирует существующее окно.
- Запуск из консоли: `npm run start:host`. При кириллице в пути ему нужен ASCII-путь к Electron:
  `$env:ELECTRON_OVERRIDE_DIST_PATH="$env:LOCALAPPDATA\VTT\electron-45.2.1"; npm run start:host`
- Иконка приложения: [icon.ico](desktop-host/build/icon.ico) (генерируется `scripts/make-icon.py`).

## Ссылка-приглашение и туннель

Панель «Приглашение» показывает три адреса: локальный, по локальной сети и через туннель.
Ссылка-приглашение выбирается так: туннель → LAN → localhost.

- Кнопка **«Запустить туннель cloudflared»** поднимает quick-туннель
  `cloudflared tunnel --no-autoupdate --url http://localhost:3001` и подставляет полученный
  `https://*.trycloudflare.com` в ссылку. Требуется установленный `cloudflared` в PATH.
- Если `cloudflared` не установлен, вставьте адрес своего туннеля (ngrok, cloudflared,
  reverse-proxy) в поле «Сохранить» — ссылка будет сформирована с его учётом.
- Туннелировать нужно только порт **3001** (в собранном варианте он же отдаёт веб-клиент).

## Где хранятся данные

`<userData>/vtt-data/<sessionId>/session.json` и `<sessionId>/assets/*` — на Windows это
`%APPDATA%\desktop-host\vtt-data`. Изображения копируются в папку сессии, в JSON хранятся
относительные пути (уточнение 5). Путь можно переопределить переменной окружения
`VTT_DATA_DIR`, порт — `VTT_PORT`.

Автосохранение: изменения пишутся на диск с задержкой ~250 мс (атомарно, через `.tmp` + rename),
а также принудительно при закрытии приложения.

## Проверки

```powershell
npm run typecheck   # tsc strict во всех пакетах
npm run lint        # ESLint
npm run format      # Prettier
npm run build       # production-сборка
npm run test:server # интеграционный тест сервера (сессии, сокеты, токены, чат, кубики, туман, файлы)
```

`test:server` поднимает сервер на порту 3999, подключает socket.io-клиента и проверяет
вход в сессию, права (туман войны — только Мастер, скрытые токены не уходят игрокам),
перемещение токенов, чат, кубики, рисование, отдачу файлов и защиту от path traversal.

## Дополнения после v1.0

- **Имена токенов.** Мастер переименовывает токены в панели «Токены» (карандаш
  или двойной клик по имени) и в панели выбранного токена. Имена сохраняются в
  сессии и синхронизируются всем участникам.
- **Текст на карте.** Инструмент **«Текст»** (кнопка `T`) ставит заметку в любую
  точку карты: клик — ввод, `Ctrl+Enter` — сохранить, `Esc` — отмена. Цвет и
  размер шрифта выбираются в панели инструмента. Заметку можно перетаскивать
  инструментом «Выбор», править двойным кликом и удалять клавишей `Delete`.
  Тексты общие для сессии, добавлять может любой участник, править и удалять —
  автор или Мастер.
- **Цвета сетки и имён.** В панели «Карта и сетка» задаются цвет линий сетки и
  цвет подписей токенов. Там же есть общий переключатель «Показывать имена»;
  имя отдельного токена можно скрыть кнопкой «Имя» в панели выбранного токена.
  У выбранного токена подпись остаётся видимой.
- **Расширения.** Кнопка с пазлом в правом нижнем углу открывает широкий каталог
  модулей с разделами, как в Owlbear Rodeo: **«Базовые»** (кубики, чат, рисование,
  туман войны, подписи токенов), **«Тройка!»** (инициатива, листы персонажей и
  панель умений), **«AZAG»** (лист персонажа AZAG), **«Запретные земли»**
  (лист персонажа), **«Клинки во тьме»** (бланки персонажей и команд) и
  **«Библиотека»** (PDF и заметки).
  Включает и выключает расширения только Мастер, сразу для всей сессии
  (`Session.enabledExtensions`). Игроки видят тот же набор: у них панель только
  для просмотра, а иконки в правом верхнем углу позволяют разворачивать и
  сворачивать уже активированные модули. Реестр — `shared/plugins/builtins.ts`,
  разделы — `EXTENSION_CATEGORIES`. В «Базовых» есть «3D-кубики»,
  «HP/AC и состояния» и «Инициатива».
- **Модуль «Лист «Запретные земли»».** Расширение `forbidden-lands-sheet` в
  разделе **«Запретные земли»** — интерактивный двухстраничный лист персонажа
  по предоставленному PDF-бланку: характеристики и состояния, 16 навыков,
  бой, Воля, достоинства, отношения, снаряжение, скакун, запасы и монеты.
  Поля взяты из AcroForm редактируемого PDF; кружки «Опыт» и «Воля» —
  кликабельные чекбоксы. Фон страниц — рендер PDF; поля наложены поверх.
  Каждый клиент выбирает свой лист, правки сливаются; окно использует
  `CharacterSheetFrame` (зум 50–200% и изменяемый размер).
- **Кубы «Запретных земель».** Модуль `fl-dice` в разделе **«Запретные земли»**:
  пул белых (атрибут), красных (навык), чёрных (снаряжение) d6 и дополнительных
  d8/d10/d12; 6–7 — 1 успех, 8–9 — 2, 10–11 — 3, 12 — 4; модификатор, помощь,
  сложность; один **«Рискнуть»**. 1 на красных, d8/d10/d12 не является баном и
  перебрасывается. Результат уходит в общий чат. Пока без автоматического
  применения урона/Волы к листу.
- **Модуль «Инициатива «Тройка»».** Готовое расширение из Owlbear Rodeo
  (`troika-initiative`) подключено **без изменения исходников**: файлы лежат в
  [desktop-host/extensions/troika-initiative](desktop-host/extensions/troika-initiative),
  хост отдаёт их по `/extensions/...`, а в `app.js` при отдаче подменяется только
  URL импорта OBR SDK на локальный адаптер `obr-shim.js`. Адаптер связывает
  метаданные сцены с `extensionState` сессии, поэтому стек инициативы общий:
  Мастер управляет, игроки видят. Подробности — в
  [desktop-host/extensions/README.md](desktop-host/extensions/README.md).
- **Модуль «Лист персонажа «Тройка»».** Второе расширение из Owlbear Rodeo
  (`troika-sheet`) подключено так же, без изменения исходников. **Листы могут
  редактировать все участники**, изменения сразу уходят на сервер и
  синхронизируются всем. У каждого пользователя **свой выбранный лист**:
  переключение не переключает остальных, а правки разных листов объединяются
  без потерь. Состояние хранится в `extensionState['troika-sheet']`.
  Панель листа масштабируется кнопками `− / % / +` в заголовке (50–200%);
  клик по проценту сбрасывает на 100%, масштаб запоминается для этого клиента.
  Само окно листа можно растягивать за правый нижний угол или края — размер
  также запоминается. Все листы используют общий `CharacterSheetFrame`;
  правило и чек-лист — [docs/character-sheets.md](docs/character-sheets.md).
- **Модуль «Тройка! Трекер состояний».** GM-панель выбранного токена вместо
  HP/AC: **Умение**, **Инициатива**, **Выносливость** (MAX и текущая),
  **Удача** (MAX и текущая), **Особенности** (свободный текст) и все общие
  состояния. Состояния меняются у токена, числовые поля и текст хранятся в
  `extensionState['troika-token-stats']` по id токена.
- **«Клинки во тьме».** Два модуля с **одним пустым бланком** каждый:
  `bitd-sheets` — бланк персонажа, `bitd-crews` — бланк команды (две страницы).
  Поверх PDF наложены редактируемые строки и чекбоксы; значения сохраняются
  локально у клиента. PDF отображается локальным PDF.js с масштабом и
  переходом по страницам. Подробности —
  [docs/blades-in-the-dark.md](docs/blades-in-the-dark.md).
- **Модуль «Лист персонажа AZAG».** Третий модуль — лист персонажа для игры
  AZAG (Dank Dungeons), сделанный по PDF-бланку `Лист AZAG А4.pdf`: 61 поле,
  включая 3 чекбокса, поверх отрисованной страницы. Живёт в разделе **«AZAG»**,
  функции те же, что у листа «Тройки»: общее состояние, редактирование всеми,
  свой выбранный лист у каждого, объединение правок разных листов.
  Окно шире обычных панелей; масштаб `− / % / +` работает так же, как у «Тройки»,
  а размер окна можно менять перетаскиванием краёв.
  Состояние — `extensionState['azag-sheet']`.
- **3D-кубики.** Модуль «3D-кубики» бросает физические d4–d100 на 3D-столе
  (Three.js + Cannon, локально, без CDN). Результат показывается в панели и
  уходит в общий чат, поэтому его видят все участники. Модуль лежит в разделе
  «Базовые».
- **PDF-библиотека.** Модуль **«PDF-библиотека»** (`pdf-viewer`) в разделе
  «Библиотека»: Мастер загружает PDF через системный диалог, файл копируется в
  папку сессии и раздаётся с поддержкой Range. Все участники читают документ во
  встроенном PDF.js-просмотрщике: страницы, масштаб, «по ширине». Ограничение —
  500 МБ на документ. Подробности — [docs/library.md](docs/library.md).
- **Заметки.** Модуль **«Заметки»** (`notes`): общий журнал кампании, заметки
  только для Мастера и локальные «Мои заметки». Markdown с предпросмотром,
  поиск и теги, автосохранение. GM-заметки вырезаются сервером и не попадают
  игрокам; личные заметки хранятся в `localStorage` клиента.
  Подробности — [docs/library.md](docs/library.md).
- **HP/AC и состояния.** Модуль «HP/AC и состояния» рисует над токенами полосу
  здоровья, временные HP, класс брони и маркеры состояний (яд, оглушение,
  концентрация и др.). Видимость цифр настраивается на токен: все видят /
  только полоса / скрыто. Редактирует Мастер, игроки видят результат; цифры
  скрытых статов не уходят в сокет.
- **Инициатива.** Универсальный трекер боя: порядок ходов, раунды, инициатива
  с бонусом и броском d20, скрытые NPC, HP и состояния из статов токена,
  подсветка активного токена и объявления хода в чат. Панель общая, игроки
  видят её только для чтения; «Тройка» остаётся отдельным модулем со стеком.
- **Туман у Мастера.** В режиме «туман виден» превью строится как бинарная
  маска: пиксель либо полностью закрыт туманом, либо полностью открыт.
  Полутона по краям мазков и следы многократного ластика больше не видны —
  остаётся только наличие тумана или его отсутствие. В режиме «туман скрыт»
  Мастер видит закрытые области полупрозрачным затемнением (45%): карта,
  сетка и токены остаются читаемыми, поэтому в этом режиме можно вести
  партию. Игроки всегда видят плотный туман.
- **Несколько карт.** Карты можно раскладывать **в ряд или в столбец** на общем
  полотне с зазором 120 px; переключение — перетаскивание полотна, токены
  переносятся между картами. Каждую карту можно **поворачивать** (шаг 15°) и
  **масштабировать**. В левом нижнем углу — мини-индикатор карт (клик центрирует
  карту), в панели «Карта и сетка» — перестановка, поворот, масштаб и удаление.
  Туман войны и рисунки общие на весь мир. Старые сессии с одной картой
  открываются миграцией (`schemaVersion: 2`).
  **GIF-карты анимируются**: кадры декодируются через `ImageDecoder` и слой
  перерисовывается до 30 FPS; GIF-токены пока остаются статичными.
  **Видео (MP4/WebM/MOV) при загрузке конвертируется в GIF**: первые 15 секунд,
  до 900 px по длинной стороне, 12 кадров/с; прогресс показывается уведомлением.
  Подробности — [docs/multi-map.md](docs/multi-map.md).
- **«Запретные земли».** Реализованы лист персонажа и кубы; карточная
  инициатива, путешествия и укрепление — в бэклоге.
  Подробности — [docs/forbidden-lands.md](docs/forbidden-lands.md).

## WebSocket API

Сервер — источник истины: проверяет роли, ограничивает размеры данных и сохраняет изменения.

**Host → Client**

| Событие                      | Данные                                                  |
| ---------------------------- | ------------------------------------------------------- |
| `session:update`             | `Session` (без скрытых токенов)                         |
| `session:closed`             | `{ reason }`                                            |
| `players:update`             | `PlayerInfo[]`                                          |
| `token:add` / `token:remove` | `Token` / `{ tokenId }`                                 |

## Уточнения из ТЗ, учтённые в реализации

1. **Туннель.** `cloudflared` запускается из панели приглашения; можно вставить готовый адрес
   туннеля вручную.
2. **Камера.** Позиция и масштаб хранятся в `localStorage` каждого клиента
   (`vtt.camera.*`) и не синхронизируются. Камера не центрируется сама при
   добавлении или загрузке карт: положение сохраняется между обновлениями сессии.
   Кнопка «Вписать» в правом нижнем углу вписывает **карту под центром экрана**,
   а не всё полотно из нескольких карт.
3. **Типы данных.** `Token`, `FogOfWarData`, `Drawing`, `DrawingInput`, `TokenPatch`,
   `PlayerInfo` спроектированы и описаны в `shared/types`.
4. **Токены.** Перемещение и изменение размера доступны и Мастеру, и игрокам;
   закреплённый токен (`locked`) двигать нельзя.
5. **Изображения.** Копируются в `<session>/assets/`, в JSON — относительные пути.
6. **Приватных сообщений нет** — только общий чат.
7. **Роли.** GM — только хост через Electron; все веб-клиенты — игроки. GM-only действия
   (туман войны, скрытие и добавление токенов, настройки сессии) выполняются через IPC
   главного процесса, а сервер проверяет роль на сокете.
8. **Репозиторий.** `desktop-host/`, `web-client/` и `shared/` лежат в корне.

## Решения по реализации

- **Общий канвас.** Konva-компоненты, панели чата/кубиков и плавающие окна вынесены в
  `shared/ui`, поэтому Мастер и игроки видят одинаковую картинку и поведение.
- **Туман войны** хранится как список операций над базовым состоянием (`covered`),
  а не как пиксельная маска: JSON остаётся компактным, операции обратимы.
- **Ластик рисования** — линия с `globalCompositeOperation: destination-out` в отдельном
  слое: он стирает только рисунки, не карту и не токены.
- **Производительность.** Сетка рисуется одним `Shape` с отсечением по видимой области;
  перемещение токена рассылается точечным `token:update` (не полным состоянием), а полная
  рассылка `session:update` используется для структурных изменений.
- **Отключения.** Socket.io переподключается сам; клиент повторно входит в сессию,
  камера и инструменты восстанавливаются, состояние стола остаётся на экране.

## Ограничения v1.0

- История чата и бросков ограничена (500 сообщений / 200 бросков) и хранится в JSON сессии.
- Токены — квадратные изображения со скруглением; анимированные GIF-токены не
  поддерживаются (GIF-карты поддерживаются).
- Для гексов размер ячейки трактуется как ширина гекса.
- Масштаб камеры ограничен 5%…800%.
- Несколько карт можно раскладывать в ряд или в столбец, поворачивать и
  масштабировать; туман и рисунки общие на мир.

## Возможные проблемы

- **`npm` не запускается в PowerShell** — политика выполнения скриптов: используйте `npm.cmd`.
- **`Electron uninstall` при `npm run dev:host`** — не скачался бинарник Electron:
  `node node_modules/electron/install.js`.
- **`Cannot read properties of undefined (reading 'requestSingleInstanceLock')`** —
  в окружении задана переменная `ELECTRON_RUN_AS_NODE=1`, и Electron запускается как Node.
  Ярлык убирает её сам; при запуске из консоли удалите вручную:
  `Remove-Item Env:ELECTRON_RUN_AS_NODE`.
- **Ярлык запускается, но окно не появляется** — почти всегда кириллица в пути к проекту:
  Chromium/Electron падает ещё до запуска JS. Лаунчер обходит это, копируя Electron
  в `%LOCALAPPDATA%\VTT\electron-<версия>`; проверьте `desktop-host\out\launcher.log`.
  Если проект переносили — пересоздайте ярлык командой `npm run shortcut`.
- **`npm run dev:host` / `npm run start:host` падают сразу** — тот же путь с кириллицей.
  Задайте ASCII-путь к Electron:
  `$env:ELECTRON_OVERRIDE_DIST_PATH="$env:LOCALAPPDATA\VTT\electron-45.2.1"`.
- **Порт 3001 занят** — задайте другой: `$env:VTT_PORT=3010; npm run dev:host`
  (и укажите этот порт в `web-client/.env.local` как `VITE_HOST_URL=http://localhost:3010`).
- **Игроки не подключаются по LAN** — разрешите Node/Electron входящие подключения
  в брандмауэре Windows для порта 3001.
